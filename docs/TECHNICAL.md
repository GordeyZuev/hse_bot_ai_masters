### 📊 Упрощенная схема

```
        ┌─────────┐
        │  USER   │
        └────┬────┘
             │

    │      BOT        │◄──────┐
    │  (Telegram API) │       │

         │                    │
         │                    │
    ┌────▼────────────┐       │
    │   DATABASE      │       │

    └────┬────────────┘       │
         │                    │
         │                    │
    ┌────▼────────────┐       │
    │   SCHEDULER     │───────┘
    │ (APScheduler)   │
    └────┬────────────┘
         │
         ▼
    ┌─────────────┐
    │GOOGLE SHEETS│
    │ (Data Source)│
    └─────────────┘
```

**Основные компоненты:**
- **USER** - пользователи Telegram
- **BOT** - обработка команд и сообщений (aiogram)
- **DATABASE** - хранение данных (пользователи, дедлайны, настройки)
- **SCHEDULER** - планирование задач (синхронизация, уведомления)
- **GOOGLE SHEETS** - источник данных о дедлайнах

**Потоки:**
- USER ↔ BOT ↔ DATABASE (команды, настройки, подписки)
- SCHEDULER → DATABASE (планирование уведомлений)
- SCHEDULER → GOOGLE SHEETS → DATABASE (синхронизация данных)
- SCHEDULER → DATABASE → BOT → USER (отправка уведомлений)

### 🔄 Потоки данных

#### 1. **Синхронизация данных**
```
Scheduler → GSheetsSyncer → DataSyncer → DatabaseManager → PostgreSQL
    ↓              ↓              ↓              ↓
  Timer        HTTP API      Transform      SQLAlchemy
```

#### 2. **Обработка команд пользователя**
```
Telegram → Middleware → Handler → Service → DatabaseManager → Response
    ↓           ↓          ↓         ↓            ↓
  Webhook    User Mgmt   Business   Data        SQLAlchemy
```

#### 3. **Система уведомлений**
```
Scheduler → NotificationScheduler → ScheduledNotification → NotificationSender → Telegram (Users)
    ↓              ↓                        ↓                      ↓
  Timer        Planning                Database              HTTP API

Scheduler → ChatNotificationScheduler → ChatScheduledNotification → ChatNotificationSender → Telegram (Chats)
    ↓              ↓                            ↓                          ↓
  Timer        Planning                    Database                    HTTP API
```

#### 4. **Система мгновенных уведомлений об изменениях**
```
Sync (DataSyncer) → Task Changes Detector → NotificationSender.send_immediate_task_changes → Telegram
    ↓                          ↓                                  ↓
  Sheets              Изменения только soft/hard          Группировка и отправка
                    дедлайнов (не названий/ссылок)        с показом изменений
```

#### 5. **Работа с групповыми чатами**
```
Telegram Chat → GroupChat Handler → ChatService → ChatNotificationScheduler → ChatNotificationSender → Telegram Chat/Topic
    ↓                  ↓                ↓                       ↓                          ↓
  /start cmd      Настройка чата    БД (Chat)             Планирование              HTTP API
                                                   уведомлений для чатов
```

## 💬 Работа с групповыми чатами (v1.1.0)

### 🏗️ Архитектура групповых чатов

Система поддерживает работу в групповых чатах и супергруппах Telegram, включая форумы с топиками (Topics).

#### 🔄 Режимы работы чатов

Бот поддерживает два режима работы в групповых чатах:

1. **Single-mode** — одна дисциплина на весь чат
   - Все топики получают уведомления по одной дисциплине
   - Настройка применяется ко всему чату
   - Идеально для чатов, посвященных одному предмету

2. **Multi-mode** — каждая дисциплина в своем топике
   - Каждый топик может отслеживать свою дисциплину независимо
   - Независимая настройка уведомлений для каждого топика
   - Идеально для чатов с несколькими предметами

#### 📊 Потоки данных для чатов

```
1. Настройка чата:
Telegram Chat → /start → GroupChatHandler → ChatService → Database (Chat)
                                                        ↓
                                                 Привязка к предмету

2. Планирование уведомлений:
New/Updated Task → ChatNotificationScheduler → ChatScheduledNotification → Database
                    ↓
              Для всех чатов по предмету

3. Отправка уведомлений:
Scheduler → ChatNotificationSender → ChatScheduledNotification → Telegram Chat/Topic
              ↓
        Батч-обработка по чатам
```

### 🗄️ Модели базы данных

#### Chat
- **`chat_id`** (BigInteger, PK) - ID чата в Telegram
- **`mode`** (Text) - Режим работы: 'single' или 'multi'
- **`chat_type`** (Text) - 'group' или 'supergroup'
- **`chat_title`** (Text, nullable) - Название чата

#### ChatTopic
- **`chat_id`** (BigInteger, FK) - Связь с чатом
- **`topic_id`** (BigInteger, nullable) - ID топика (None = общий чат, число = топик форума)
- **`topic_title`** (Text, nullable) - Отображаемое имя топика (кеш)
- **`subject_id`** (Integer, FK) - Привязка к предмету
- **`reminder1_offset/unit`** - Настройки первого напоминания
- **`reminder2_offset/unit`** - Настройки второго напоминания
- **`is_active`** (Boolean) - Активность топика

**Особенности:**
- В Single-mode: один топик на весь чат (обычно с `topic_id = None`)
- В Multi-mode: несколько топиков, каждый со своей дисциплиной

#### ChatScheduledNotification
- **`chat_topic_id`** (Integer, FK) - Связь с топиком чата
- **`chat_id`** (BigInteger) - ID чата для удобства группировки
- **`topic_id`** (BigInteger, nullable) - ID топика для удобства
- **`deadline_id`** (Integer, FK) - Связь с дедлайном
- **`deadline_type`** (Text) - 'soft' или 'hard'
- **`notification_number`** (Integer) - 1 или 2
- **`original_deadline_ts`** (DateTime) - Исходное время дедлайна
- **`planned_delivery_time`** (DateTime) - Запланированное время отправки
- **`status`** (Text) - 'scheduled', 'sent', 'cancelled', 'failed'

### 🔧 Сервисы для чатов

#### ChatService
- Управление групповыми чатами
- Поддержка двух режимов работы (Single-mode и Multi-mode)
- Привязка чатов и топиков к предметам
- Обновление настроек уведомлений для чатов и топиков
- Переключение между режимами работы

#### ChatNotificationSchedulerService
- Планирование уведомлений для чатов
- Автоматическое создание уведомлений при добавлении чата
- Перепланирование при изменениях дедлайнов

#### ChatNotificationSender
- Отправка уведомлений в групповые чаты
- Поддержка отправки в топики форумов
- Батч-обработка для эффективной доставки
- Группировка нескольких дедлайнов в одно сообщение

#### ChatEventsService
- Обработка событий добавления/удаления бота из чата
- Автоматическая деактивация чата при удалении бота

### 📝 Обработчики для чатов

#### `group_chat.py`
- **`/start` в чатах** - Настройка чата на предмет
- **Интерактивные кнопки** - Выбор предмета, настройка уведомлений
- **Callback handlers** - Обработка действий пользователей

### 🎯 Особенности реализации

#### Отправка в топики
- Если `topic_id` установлен, уведомления отправляются в соответствующий топик
- Если топик закрыт или недоступен, сообщение отправляется в общий чат

#### Форматирование уведомлений
- Без нумерации для одного дедлайна (как в личных чатах)
- Группировка нескольких дедлайнов с нумерацией
- Единый формат с уведомлениями для пользователей

## 📝 Форматирование уведомлений

Система отслеживает только изменения дат дедлайнов (soft_deadline_ts, hard_deadline_ts). При обновлении дедлайна в уведомлении показывается новое значение и перечеркнутое старое. Новые и обновленные дедлайны отображаются в отдельных секциях.

## ⏰ Режим сна и управление уведомлениями

**Режим сна (Do Not Disturb):** Пользователи могут настроить время сна, в течение которого уведомления отправляются без звука (`disable_notification=True`). Поддерживается пересечение полночи (например, 23:00 - 08:30). Настройки хранятся в `UserNotificationSettings` (поля `sleep_start_time`, `sleep_end_time`).

**Управление уведомлениями об обновлениях:** Пользователи могут отключить мгновенные уведомления об изменениях дедлайнов через настройку `enable_deadline_update_notifications`. Запланированные напоминания продолжают работать независимо от этой настройки.

## ✅ Система отслеживания статуса заданий (v1.0.0)

Система позволяет пользователям отмечать задания как выполненные. Выполненные задания:
- Автоматически исключаются из уведомлений
- Могут быть скрыты из списка дедлайнов
- При отметке все запланированные уведомления отменяются
- При снятии отметки уведомления автоматически перепланируются

**Модель БД:** `TaskUserStatus` (связь user_id + deadline_id)

**Сервис:** `TaskStatusService` - управление статусом выполнения

**Интеграция:** Выполненные задания исключаются на уровне БД при планировании и отправке уведомлений

## 🛠️ Утилиты для работы с Telegram API (v1.0.0)

### 📦 Модуль `src/bot/middlewares/private_chat.py`

Функции `safe_edit_message()` и `safe_send_message()` перенесены из `src/utils/telegram.py` в middleware для более централизованной обработки ошибок. Доступны через `src/utils/__init__.py` для обратной совместимости (ленивая загрузка).

#### `TelegramErrorHandler`
Централизованный класс для обработки ошибок Telegram API:
- `deactivate_user(user_id)` - деактивирует пользователя в БД при блокировке бота
- `is_ignorable_error(error)` - проверяет, является ли ошибка некритичной (можно игнорировать)
- `handle_telegram_error(error, user_id=None)` - обрабатывает ошибку и возвращает `True` если ошибка обработана

#### `PrivateChatMiddleware`
Middleware для автоматической обработки ошибок в личных чатах:
- Перехватывает `TelegramBadRequest` и `TelegramForbiddenError` для личных чатов
- Автоматически деактивирует пользователей при блокировке бота
- Игнорирует некритичные ошибки (например, "message is not modified")

#### `safe_edit_message(message, text, **kwargs)`
Безопасное редактирование сообщения с обработкой ошибок Telegram API.

**Обрабатываемые ошибки:**
- `"message is not modified"` - сообщение не изменилось (игнорируется, возвращает `False`)
- `"message not found"` - сообщение удалено (игнорируется, возвращает `False`)
- `TelegramForbiddenError` - бот заблокирован (игнорируется, возвращает `False`)
- Прочие исключения пробрасываются дальше

**Возвращает:** `bool` - `True` если сообщение успешно отредактировано, `False` если произошла ошибка

#### `safe_send_message(bot, chat_id, text, user_id=None, success_message=None, **kwargs)`
Безопасная отправка сообщения с автоматической обработкой ошибок, логированием и деактивацией.

**Особенности:**
- **Автоматическое применение режима сна**: если передан `user_id`, автоматически проверяет режим сна пользователя и применяет `disable_notification=True` при необходимости
- **Автоматическая деактивация**: при `TelegramForbiddenError` (бот заблокирован) автоматически деактивирует пользователя через `TelegramErrorHandler.deactivate_user()`
- **Логирование**: логирует успешные отправки (если передан `success_message`) и ошибки

**Обрабатываемые ошибки:**
- `TelegramForbiddenError` - бот заблокирован (логирует + деактивирует пользователя, возвращает `False`)
- `TelegramBadRequest` - различные ошибки API (логирует, не деактивирует, возвращает `False`)
- Прочие исключения пробрасываются дальше

**Возвращает:** `bool` - `True` если отправка успешна, `False` если была ошибка

### 📦 Модуль `src/bot/middlewares/group_chat.py`

#### `GroupChatMiddleware`
Middleware для обработки ошибок в групповых чатах:
- Перехватывает ошибки закрытых топиков (`topic_closed`)
- Автоматически отправляет уведомление в общий чат при недоступности топика
- Получает название топика из сообщения или через API для информативных уведомлений
- Логирует ошибки групповых чатов без прерывания основного потока

**Особенности:**
- Автоматическое определение закрытых топиков
- Информативные уведомления с указанием прав, необходимых боту
- Безопасная обработка ошибок без прерывания работы бота

### 📦 Утилиты

**`src/utils/__init__.py`** - Ленивая загрузка функций из middleware для избежания циклических импортов (`safe_edit_message`, `safe_send_message`).

**`src/utils/notification.py`** - Утилиты для работы с уведомлениями:
- `apply_sleep_mode()` - применение режима сна к сообщениям

**Использование:**
- Все сервисы используют `safe_send_message()` и `safe_edit_message()` для безопасной работы с Telegram API
- Режим сна автоматически применяется для личных сообщений
- Ошибки обрабатываются автоматически через middleware
