## 🤖 Добавление бота в групповой чат

Бот поддерживает два режима работы в групповых чатах:

### Single-mode (одна дисциплина на весь чат)

В этом режиме весь чат отслеживает дедлайны одной дисциплины. Настройка применяется ко всему чату сразу.

**📝 Пошаговая инструкция:**

1. **Добавьте бота в чат**
   - Откройте настройки группы/супергруппы
   - Перейдите в раздел "Участники" → "Добавить участников"
   - Найдите бота по имени и добавьте его
   - **Важно:** Убедитесь, что бот имеет права администратора (рекомендуется включить "Управление темами форума" для работы с закрытыми топиками)

2. **Настройте бота**
   - В общем чате или в любом топике вызовите команду `/start` или нажмите кнопку "⚙️ Настроить бота"
   - Выберите режим **"1️⃣ Single-mode"**
   - Выберите предмет из списка доступных дисциплин
   - При необходимости настройте параметры уведомлений:
     - Первое напоминание (по умолчанию: за 7 дней)
     - Второе напоминание (по умолчанию: за 1 день)
   - Нажмите "✅ Готово"

3. **Готово!**
   - Бот начнет отправлять уведомления о дедлайнах выбранной дисциплины
   - Все топики будут получать одинаковые уведомления

**💡 Полезные команды:**
- `/chat_settings` — просмотр и изменение настроек чата
- `/info` — информация о предмете и актуальные дедлайны
- `/disable_chat` — временно отключить уведомления в чате

---

### Multi-mode (каждая дисциплина в своем топике)

В этом режиме каждый топик может отслеживать дедлайны своей дисциплины. Настройка выполняется отдельно для каждого топика.

**📝 Пошаговая инструкция:**

1. **Добавьте бота в чат**
   - Откройте настройки группы/супергруппы
   - Перейдите в раздел "Участники" → "Добавить участников"
   - Найдите бота по имени и добавьте его
   - **Важно:** Убедитесь, что бот имеет права администратора (обязательно включите "Управление темами форума" для работы с топиками)

2. **Выберите режим Multi-mode**
   - В общем чате вызовите команду `/start` или нажмите кнопку "⚙️ Настроить бота"
   - Выберите режим **"2️⃣ Multi-mode"**
   - Бот подтвердит установку режима

3. **Настройте каждый топик отдельно**
   - Перейдите в нужный топик (или останьтесь в общем чате, если хотите настроить его)
   - Вызовите команду `/setup_discipline` или нажмите кнопку "⚙️ Настроить бота" из `/start`
   - Выберите предмет для этого топика
   - При необходимости настройте параметры уведомлений:
     - Первое напоминание (по умолчанию: за 7 дней)
     - Второе напоминание (по умолчанию: за 1 день)
   - Нажмите "✅ Готово"

4. **Повторите для других топиков**
   - Для каждого топика, где нужны уведомления, выполните шаг 3
   - Каждый топик может отслеживать свою дисциплину независимо

**💡 Полезные команды:**
- `/start` в общем чате — просмотр всех настроенных топиков
- `/chat_settings` в топике — настройки конкретного топика
- `/info` — информация о предмете и дедлайны для текущего топика

**⚠️ Важно:**
- В Multi-mode нельзя настраивать общий чат — настройка выполняется только в топиках
- При переключении из Single-mode в Multi-mode все текущие настройки будут удалены, и нужно будет настроить каждый топик заново

## 📊 Работа с таблицей дедлайнов

Бот синхронизирует данные из Google Sheets. Для корректной работы важно правильно заполнять таблицу.

### Структура таблицы

Таблица дедлайнов должна содержать следующие колонки:

| Колонка | Описание | Обязательность |
|---------|----------|----------------|
| **ID** (или **id**, **Row ID**, **Номер строки**, **№**) | Уникальный идентификатор строки | ⚠️ **Крайне рекомендуется** |
| **Дисциплина** | Название предмета | ✅ Обязательно |
| **Название ДЗ** | Название задания | ✅ Обязательно |
| **Источник (Link)** | Ссылка на задание | ⚠️ Рекомендуется |
| **Мягкий Дедлайн** | Дата мягкого дедлайна | ⚠️ Рекомендуется |
| **Жесткий Дедлайн** | Дата жесткого дедлайна | ⚠️ Рекомендуется |
| **Комментарий** | Дополнительная информация | ❌ Опционально |

**⚠️ Важность колонки ID:**

Колонка ID является **критически важной** для корректной работы синхронизации. Бот использует ID для:

1. **Идентификации дедлайнов** — определение, является ли строка новым дедлайном или обновлением существующего
2. **Обновления данных** — при изменении информации в строке бот находит соответствующий дедлайн по ID и обновляет его
3. **Удаления устаревших дедлайнов** — если строка с определенным ID удалена из таблицы, соответствующий дедлайн будет удален из базы данных при следующей синхронизации

**Что происходит без ID:**
- Если ID отсутствует, бот использует хеш от содержимого строки
- При изменении данных (например, даты дедлайна) бот может создать дубликат вместо обновления существующего дедлайна
- При удалении строки дедлайн может остаться в базе данных, так как бот не сможет его идентифицировать
- При перемещении строки в таблице дедлайн может быть обработан как новый

**Рекомендации по ID:**
- Используйте последовательную нумерацию (1, 2, 3, ...) или уникальные идентификаторы
- **Никогда не изменяйте ID существующей строки** — это приведет к созданию дубликата
- При удалении строки просто удалите её — бот автоматически удалит соответствующий дедлайн при синхронизации
- При добавлении новой строки используйте новый уникальный ID

**Пример заполнения:**

| ID | Дисциплина | Название ДЗ | Мягкий Дедлайн | Жесткий Дедлайн | Комментарий | Источник (Link) |
|----|------------|------------|----------------|-----------------|-------------|-----------------|
| 1 | Прикладной Python | Домашнее задание 1 | 15.12.2025 | 20.12.2025 | Важно! | https://... |
| 2 | Машинное обучение | Проект | 25.12.2025 | 30.12.2025 | | https://... |

### Важные правила заполнения

1. **Названия дисциплин должны совпадать**
   - Название в колонке "Дисциплина" должно точно совпадать с названием предмета в таблице "Дисциплины"
   - Бот автоматически очищает названия от информации о модулях (например, "Прикладной Python 1 модуль" → "Прикладной Python")
   - Если дисциплина не найдена, дедлайн будет пропущен при синхронизации

2. **Обязательные поля**
   - **Дисциплина** и **Название ДЗ** — обязательны. Строки без этих полей будут пропущены
   - Хотя бы один дедлайн (мягкий или жесткий) должен быть указан, иначе задание не будет отслеживаться

3. **Формат названий**
   - Название дисциплины может содержать информацию о модуле (например, "Прикладной Python 1 модуль")
   - Бот автоматически извлекает номер модуля и очищает название
   - Модуль используется для группировки дедлайнов

4. **Уникальность заданий**
   - Каждое задание должно иметь уникальное сочетание дисциплины и названия
   - При обновлении дедлайна с тем же названием бот обновит существующую запись

### Формат дат

Бот поддерживает различные форматы дат. Рекомендуемые форматы:

- `15.12.2025` (день.месяц.год)
- `15 декабря 2025`
- `2025-12-15`
- `15/12/2025`

**Важно:**
- Если время не указано, бот автоматически установит время **23:59**
- Даты интерпретируются в часовом поясе, указанном в настройках (по умолчанию: Europe/Moscow)
- Бот автоматически конвертирует даты в UTC для хранения в базе данных

**Примеры корректных дат:**
- `15.12.2025` → 15 декабря 2025, 23:59
- `15.12.2025 18:00` → 15 декабря 2025, 18:00
- `2025-12-15` → 15 декабря 2025, 23:59

### Синхронизация данных

1. **Автоматическая синхронизация**
   - Бот периодически синхронизирует данные из Google Sheets (по расписанию)
   - При обнаружении изменений бот автоматически обновляет дедлайны и перепланирует уведомления

2. **Ручная синхронизация (для администраторов)**
   - Команда `/fast_sync` — быстрая синхронизация всех данных
   - Синхронизируются:
     - Дисциплины (из листа "Дисциплины")
     - Дедлайны (из листов "1_Курс_Дедлайны" и "2_Курс_Дедлайны")

3. **Что происходит при синхронизации:**
   - Новые дедлайны добавляются в базу данных (определяются по отсутствию ID в базе)
   - Изменения в существующих дедлайнах обновляются (находятся по ID)
   - Уведомления перепланируются только при изменении дат дедлайнов
   - **Удаленные из таблицы дедлайны автоматически удаляются из базы** (если у них был корректный ID)
   - Все запланированные уведомления для удаленных дедлайнов отменяются

4. **Обработка ошибок:**
   - Если дисциплина не найдена, дедлайн пропускается с предупреждением в логах
   - Если дата не распознана, дедлайн пропускается с предупреждением
   - Ошибки синхронизации логируются, но не останавливают процесс

### Рекомендации по заполнению таблицы

✅ **Делайте так:**
- **Всегда используйте колонку ID** с уникальными значениями для каждой строки
- Используйте единообразные названия дисциплин
- Заполняйте оба дедлайна (мягкий и жесткий) для лучшего отслеживания
- Добавляйте комментарии для важной информации
- Указывайте ссылки на задания в колонке "Источник (Link)"
- Регулярно обновляйте таблицу при изменении дедлайнов
- При удалении дедлайна просто удаляйте строку из таблицы (бот удалит её автоматически)

❌ **Избегайте:**
- **Изменения ID существующих строк** — это создаст дубликаты
- **Удаления колонки ID** — без неё синхронизация работает некорректно
- Пустых строк в обязательных колонках
- Разных вариантов написания одной дисциплины
- Некорректных форматов дат
- Дублирования заданий с одинаковыми названиями
- Ручного удаления дедлайнов из базы данных — используйте удаление строк из таблицы
