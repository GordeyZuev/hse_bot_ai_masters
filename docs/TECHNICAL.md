### 🔄 Потоки данных

#### 1. **Синхронизация данных**
```
Scheduler → GSheetsSyncer → DataSyncer → DatabaseManager → PostgreSQL
    ↓              ↓              ↓              ↓
  Timer        HTTP API      Transform      SQLAlchemy
```

#### 2. **Обработка команд пользователя**
```
Telegram → Middleware → Handler → Service → DatabaseManager → Response
    ↓           ↓          ↓         ↓            ↓
  Webhook    User Mgmt   Business   Data        SQLAlchemy
```

#### 3. **Система уведомлений**
```
Scheduler → NotificationScheduler → ScheduledNotification → NotificationSender → Telegram (Users)
    ↓              ↓                        ↓                      ↓
  Timer        Planning                Database              HTTP API

Scheduler → ChatNotificationScheduler → ChatScheduledNotification → ChatNotificationSender → Telegram (Chats)
    ↓              ↓                            ↓                          ↓
  Timer        Planning                    Database                    HTTP API
```

#### 4. **Система мгновенных уведомлений об изменениях**
```
Sync (DataSyncer) → Task Changes Detector → NotificationSender.send_immediate_task_changes → Telegram
    ↓                          ↓                                  ↓
  Sheets              Изменения только soft/hard          Группировка и отправка
                    дедлайнов (не названий/ссылок)        с показом изменений
```

#### 5. **Работа с групповыми чатами**
```
Telegram Chat → GroupChat Handler → ChatService → ChatNotificationScheduler → ChatNotificationSender → Telegram Chat/Topic
    ↓                  ↓                ↓                       ↓                          ↓
  /start cmd      Настройка чата    БД (ChatGroup)        Планирование              HTTP API
                                                   уведомлений для чатов
```

## 💬 Работа с групповыми чатами (v1.0.0)

### 🏗️ Архитектура групповых чатов

Система поддерживает работу в групповых чатах и супергруппах Telegram, включая форумы с топиками (Topics).

#### 📊 Потоки данных для чатов

```
1. Настройка чата:
Telegram Chat → /start → GroupChatHandler → ChatService → Database (ChatGroup)
                                                        ↓
                                                 Привязка к предмету

2. Планирование уведомлений:
New/Updated Task → ChatNotificationScheduler → ChatScheduledNotification → Database
                    ↓
              Для всех чатов по предмету

3. Отправка уведомлений:
Scheduler → ChatNotificationSender → ChatScheduledNotification → Telegram Chat/Topic
              ↓
        Батч-обработка по чатам
```

### 🗄️ Модели базы данных

#### ChatGroup
- **`chat_id`** (BigInteger, PK) - ID чата в Telegram
- **`topic_id`** (BigInteger, nullable) - ID топика (None = общий чат, число = топик форума)
- **`topic_title`** (Text, nullable) - Отображаемое имя топика (кеш)
- **`chat_type`** (Text) - 'group' или 'supergroup'
- **`subject_id`** (Integer, FK) - Привязка к предмету
- **`reminder1_offset/unit`** - Настройки первого напоминания
- **`reminder2_offset/unit`** - Настройки второго напоминания
- **`is_active`** (Boolean) - Активность чата

#### ChatScheduledNotification
- **`chat_group_id`** (BigInteger, FK) - Связь с чатом
- **`deadline_id`** (Integer, FK) - Связь с дедлайном
- **`deadline_type`** (Text) - 'soft' или 'hard'
- **`notification_number`** (Integer) - 1 или 2
- **`original_deadline_ts`** (DateTime) - Исходное время дедлайна
- **`planned_delivery_time`** (DateTime) - Запланированное время отправки
- **`status`** (Text) - 'scheduled', 'sent', 'cancelled', 'failed'

### 🔧 Сервисы для чатов

#### ChatService
- Управление групповыми чатами
- Привязка чатов к предметам
- Обновление настроек уведомлений для чатов

#### ChatNotificationSchedulerService
- Планирование уведомлений для чатов
- Автоматическое создание уведомлений при добавлении чата
- Перепланирование при изменениях дедлайнов

#### ChatNotificationSender
- Отправка уведомлений в групповые чаты
- Поддержка отправки в топики форумов
- Батч-обработка для эффективной доставки
- Группировка нескольких дедлайнов в одно сообщение

#### ChatEventsService
- Обработка событий добавления/удаления бота из чата
- Автоматическая деактивация чата при удалении бота

### 📝 Обработчики для чатов

#### `group_chat.py`
- **`/start` в чатах** - Настройка чата на предмет
- **Интерактивные кнопки** - Выбор предмета, настройка уведомлений
- **Callback handlers** - Обработка действий пользователей

### 🎯 Особенности реализации

#### Отправка в топики
- Если `topic_id` установлен, уведомления отправляются в соответствующий топик
- Если топик закрыт или недоступен, сообщение отправляется в общий чат

#### Форматирование уведомлений
- Без нумерации для одного дедлайна (как в личных чатах)
- Группировка нескольких дедлайнов с нумерацией
- Единый формат с уведомлениями для пользователей

## 📝 Улучшенное форматирование уведомлений (v0.9.4)

### 🎯 Умное определение обновлений

Система теперь точно определяет, что считается обновлением дедлайна:

- ✅ **Обновление** — изменение `soft_deadline_ts` или `hard_deadline_ts`
- ❌ **Не обновление** — изменение `hw_name`, `source_link`, `note` или других полей

### ✨ Показ изменений

При обновлении дедлайна в уведомлении отображается:

1. **Новое значение** — текущий дедлайн
2. **Старое значение** — перечеркнутое (`<s>`) в скобках

**Пример:**
```
🟡 Мягкий дедлайн: 01.11.2025 в 21:20 (<s>01.11.2025 в 21:15</s>)
```

### 📌 Различение новых и обновленных дедлайнов

- ✨ **Новые дедлайны** — отдельная секция без указания изменений
- 📌 **Обновленные дедлайны** — отдельная секция с указанием изменений

### 🔄 Техническая реализация

Метод `upsert_task` теперь возвращает детальную информацию:
- `is_new` — новый дедлайн или обновление
- `deadline_changed` — изменился ли дедлайн
- `soft_deadline_changed` / `hard_deadline_changed` — какие именно дедлайны изменились
- `old_soft_deadline_ts` / `old_hard_deadline_ts` — старые значения

## ⏰ Режим сна и управление уведомлениями (v0.9.4)

### 🛌 Режим сна (Do Not Disturb)

Режим сна позволяет настроить время, когда уведомления будут отправляться без звука (`disable_notification=True`).

#### Хранение настроек
- **`sleep_start_time`** (Time, nullable) - время начала сна (например, 23:00)
- **`sleep_end_time`** (Time, nullable) - время окончания сна (например, 08:30)
- Хранятся в таблице `UserNotificationSettings`

#### Логика определения сна
- Используется функция `is_sleep_time()` из `src/utils/time.py`
- Учитывается часовой пояс пользователя (`user.timezone`, по умолчанию `Europe/Moscow`)
- Поддерживается пересечение полночи (например, 23:00 - 08:30)
- Если `sleep_start_time == sleep_end_time`, сон считается выключенным

#### Отправка уведомлений во время сна
- Все уведомления отправляются с `disable_notification=True`
- К сообщению автоматически добавляется текст: "*Отправлено без уведомления. Доброй ночи! 😴*"
- Применяется как к запланированным уведомлениям (`ScheduledNotificationSender`), так и к мгновенным обновлениям (`NotificationSender`)

### 📌 Управление уведомлениями об обновлениях

#### Настройка
- **`enable_deadline_update_notifications`** (Boolean, default=True) - переключатель уведомлений об обновлениях
- Хранится в таблице `UserNotificationSettings`

#### Поведение
- Если `enable_deadline_update_notifications = False`, пользователь не получит мгновенные уведомления об изменениях дедлайнов
- Запланированные напоминания (reminder1, reminder2) продолжают работать независимо от этой настройки
- Настройка применяется в методе `NotificationSender.send_immediate_task_changes()`

#### Комбинирование настроек
При отправке мгновенных уведомлений об обновлениях проверяются:
1. `settings.is_active` - активны ли уведомления вообще
2. `settings.enable_deadline_update_notifications` - включены ли уведомления об обновлениях
3. `is_sleep_time()` - находится ли пользователь в режиме сна

Если все условия пройдены, уведомление отправляется (возможно, без звука в режиме сна).

## ✅ Система отслеживания статуса заданий (v1.0.0)

### 🎯 Обзор

Система позволяет пользователям отмечать задания как выполненные, что автоматически исключает их из уведомлений и позволяет скрывать из списка дедлайнов.

### 🗄️ Модель базы данных

#### TaskUserStatus
- **`user_id`** (BigInteger, PK, FK) - ID пользователя
- **`deadline_id`** (Integer, PK, FK) - ID дедлайна
- **Индекс** `ix_tus_deadline_id` на поле `deadline_id` для быстрого поиска
- **CASCADE удаление** при удалении пользователя или дедлайна

### 🔧 Сервис TaskStatusService

#### Метод `set_done(user_id, deadline_id)`
1. Создает запись `TaskUserStatus` в базе данных (или обновляет существующую через `merge`)
2. **Отменяет все запланированные уведомления** по этому заданию для пользователя:
   - Находит все `ScheduledNotification` со статусом `"scheduled"` для данного `user_id` и `deadline_id`
   - Устанавливает статус в `"cancelled"` и обновляет `updated_at`
3. Логирует действие

#### Метод `set_not_done(user_id, deadline_id)`
1. Удаляет запись `TaskUserStatus` из базы данных
2. **Перепланирует уведомления** для этого задания:
   - Получает дедлайн из базы данных
   - Получает пользователя и его настройки уведомлений
   - Вызывает `NotificationSchedulerService._schedule_notifications_for_user_deadline` для soft и hard дедлайнов (если они существуют и в будущем)
3. Логирует количество перепланированных уведомлений

### 📊 Интеграция с другими сервисами

#### DeadlineService
- Метод `get_user_deadlines()` использует LEFT JOIN с `TaskUserStatus` для определения статуса выполнения
- Параметр `hide_done=True` позволяет скрывать выполненные задания из списка
- Возвращает поле `is_done` в данных каждого дедлайна

#### NotificationSchedulerService
- Метод `_get_user_deadlines()` исключает выполненные задания при планировании уведомлений
- Использует LEFT JOIN с `TaskUserStatus` и фильтр `tus.c.deadline_id.is_(None)`

#### NotificationSender
- Метод `_get_deadlines_for_notification()` также исключает выполненные задания при отправке уведомлений
- Использует тот же подход с LEFT JOIN и фильтром

### 🎨 Пользовательский интерфейс

#### Handlers в `deadlines.py`
- **Фильтрация выполненных**: кнопка "🙈 Скрыть выполненные" / "🐵 Показать выполненные"
- **Режим отметки**: кнопка "📝 Отметить выполненные" открывает интерфейс с галочками
- **Быстрое переключение**: кнопки-галочки в режиме отметки для быстрого изменения статуса
- **Разделитель**: визуальный разделитель между выполненными и невыполненными заданиями
- **Стабильная нумерация**: номера заданий не меняются при переключении статуса (основана на ID дедлайна)

#### Форматирование списка дедлайнов
- **Невыполненные задания** отображаются первыми
- **Разделитель** "✅ Выполненные задания:" при показе выполненных
- **Выполненные задания** отображаются после разделителя
- **Специальное сообщение** при отсутствии невыполненных заданий: "Вы все выполнили! Поздравляем!"

### 🔄 Поток работы

```
1. Пользователь отмечает задание как выполненное:
   User → Handler → TaskStatusService.set_done() → Database (TaskUserStatus)
                                                      ↓
                                              ScheduledNotification (статус → "cancelled")

2. Пользователь снимает отметку:
   User → Handler → TaskStatusService.set_not_done() → Database (удаление TaskUserStatus)
                                                         ↓
                                              NotificationSchedulerService (перепланирование)

3. Просмотр дедлайнов:
   User → Handler → DeadlineService.get_user_tasks() → Database (LEFT JOIN TaskUserStatus)
                                                             ↓
                                                      Форматирование с разделителем

4. Планирование уведомлений:
   Scheduler → NotificationSchedulerService → Database (LEFT JOIN TaskUserStatus, фильтр is_done=False)
                                              ↓
                                      Создание ScheduledNotification только для невыполненных
```

## 🛠️ Утилиты для работы с Telegram API (v1.0.0)

### 📦 Модуль `src/utils/telegram.py`

#### `safe_edit_message(message, text, **kwargs)`
Безопасное редактирование сообщения с обработкой ошибок Telegram API.

**Обрабатываемые ошибки:**
- `"message is not modified"` - сообщение не изменилось (игнорируется, возвращает `False`)
- `"message not found"` - сообщение удалено (игнорируется, возвращает `False`)
- `TelegramForbiddenError` - бот заблокирован (игнорируется, возвращает `False`)
- Прочие исключения пробрасываются дальше

**Возвращает:** `bool` - `True` если сообщение успешно отредактировано, `False` если произошла ошибка

#### `safe_send_message(bot, chat_id, text, user_id=None, success_message=None, **kwargs)`
Безопасная отправка сообщения с автоматической обработкой ошибок, логированием и деактивацией.

**Особенности:**
- **Автоматическое применение режима сна**: если передан `user_id`, автоматически проверяет режим сна пользователя и применяет `disable_notification=True` при необходимости
- **Автоматическая деактивация**: при `TelegramForbiddenError` (бот заблокирован) автоматически деактивирует пользователя через `_deactivate_user()`
- **Логирование**: логирует успешные отправки (если передан `success_message`) и ошибки

**Обрабатываемые ошибки:**
- `TelegramForbiddenError` - бот заблокирован (логирует + деактивирует пользователя, возвращает `False`)
- `TelegramBadRequest` - различные ошибки API (логирует, не деактивирует, возвращает `False`)
- Прочие исключения пробрасываются дальше

**Возвращает:** `bool` - `True` если отправка успешна, `False` если была ошибка

**Внутренняя функция `_deactivate_user(user_id)`**:
- Деактивирует пользователя (устанавливает `is_active = False`)
- Используется при блокировке бота пользователем

### 📦 Модуль `src/utils/notification.py`

#### `apply_sleep_mode(user, settings, message_text)`
Применяет режим сна к тексту сообщения и определяет флаг `disable_notification`.

**Логика:**
1. Проверяет наличие настроек и пользователя
2. Определяет часовой пояс пользователя (по умолчанию `Europe/Moscow`)
3. Вызывает `is_sleep_time()` для проверки текущего времени
4. Если сейчас время сна:
   - Добавляет к тексту: `"\n\n<i>Отправлено без уведомления. Доброй ночи! 😴</i>"`
   - Возвращает `is_sleep = True`

**Возвращает:** `tuple[str, bool]` - модифицированный текст сообщения и флаг `disable_notification`

### 🔄 Использование в сервисах

#### NotificationSender
- Использует `safe_send_message()` для всех отправок пользователям
- Автоматически применяется режим сна через `apply_sleep_mode()` внутри `safe_send_message()`

#### ScheduledNotificationSender
- Использует `safe_send_message()` для отправки запланированных уведомлений
- Режим сна применяется автоматически

#### ChatNotificationSender
- Использует `safe_send_message()` для отправки в групповые чаты
- Режим сна не применяется для групповых чатов (только для личных сообщений)

#### Handlers
- Используют `safe_edit_message()` для безопасного редактирования сообщений
- Избегают ошибок при попытке редактирования неизменившегося или удаленного сообщения
